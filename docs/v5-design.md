# HiveDesk v5 설계: 한도가 차도 멈추지 않는 이어받기, 말풍선 작업 현황

상태: 구현 중 · 기준: v0.4.2 · 앞선 설계: v4(6-0 ~ 6-7)

## 0. 목표
1. 한도가 다 찬 직원의 일을 기다리게 두지 않고 **다른 계정(연결)의 직원**이 이어서 한다. 같은 체급 → 한 단계 위 체급 순.
2. 보드에 **작업 현황** 탭을 더한다. 일하는 직원만 모습으로 보이고, 하는 일을 말풍선으로 말한다. 자세한 내용은 오른쪽 사이드바에서 본다.

## 1. 지금 상태 (코드 기준)
- 한도는 이미 **연결(CLI 로그인) 단위**로 기록된다(`engine.limits`, `noteLimit(adapter)`). 한 직원이 걸리면 같은 연결의 직원은 자동 실행에서 모두 쉰다.
- 한도는 실행 도중이 아니라 **CLI가 끝난 뒤** 출력에서 감지된다(`limits.ts`). 초기화 시각을 모르면 60분으로 추정하고 `guessed`로 표시한다.
- 업무는 그 직원에게 묶인 채 초기화까지 '할 일 + 한도 오류'로 멈춘다. 다른 연결의 직원이 놀고 있어도 옮기지 않는다.
- 한도로 끝난 실행도 성과 기록의 실행 횟수에 들어가 빠른 배정의 "예상 실행 횟수"를 부풀린다.
- 실행마다 `[[PLAN]]`과 `[[STEP: n]]` 표시가 있어 단계 경계를 알 수 있다.

## 2. 한도 이어받기

### 2-1. 후보 고르기
한도에 걸린 직원 A의 업무 T를 이어받을 직원은 **A와 다른 연결**의 직원 중에서 고른다(같은 연결은 같은 한도를 쓰므로 언제나 제외).

순서: **A와 같은 체급 → 한 단계 위 체급 → 그 위**. 같은 체급 안에서는 지금 비어 있는 사람 → 이번에 이미 받은 이어받기 수가 적은 사람 → 이 종류 일의 첫 통과율이 높은 사람 → 사용량 가중치가 낮은 사람 → 곧 한도가 찰 것 같지 않은 사람 → 직급이 A와 가까운 사람 순. 관리자(총괄·팀장)는 실무 업무의 후보에서 맨 뒤로 둔다.

"할 수 있는" 조건:
- 같은 회사, 이 컴퓨터의 직원, 연결이 한도에 걸리지 않았고 앱 하루 예산(실행/분)도 남음
- 업무의 최소 체급 이상(빠른 배정의 기준 그대로)
- **관리자 전용 업무**(계획·통합)는 관리자만
- **검토 규칙**: 검토 업무는 검토 대상 작업자와 다른 모델
- **기능 차이**: 외부 연결(웹·MCP)을 쓰는 업무는 그 기능을 쓸 수 있는 직원(지금은 Claude)만
- **권한 강제력**: '읽기만' 업무는 권한을 CLI가 강제하는 직원(Claude·Codex)만. 프롬프트로만 안내하는 CLI(agy 등)로는 넘기지 않음
- 이 업무가 이미 거쳐 간 연결이 아님(같은 연결로 되돌아오지 않음)

아무도 없으면 지금처럼 기다리고, 가장 빨리 풀리는 연결의 초기화 시각을 보여 준다.

### 2-2. 기다릴지 넘길지
- 초기화 시각을 알고(`guessed` 아님) 남은 시간이 설정값(기본 20분) 이하면 기다린다.
- 추정 시각이면 "모름"으로 보고 넘긴다.

### 2-3. 단계 저장 지점과 요약 인계
- 실행 중 AI가 `[[STEP: n]]`을 낼 때마다 **앱이** 저장 지점을 만든다(토큰 0): 계획 목록, 끝난 단계 수, 그때까지 바뀐 파일(최대 30개), AI의 마지막 말 한두 줄. git 폴더면 그 순간의 숨은 체크포인트도 찍는다.
- 한도에 걸리면 마지막 저장 지점으로 인계 요약을 만들어(약 1천 토큰 이하) 다른 연결의 직원이 **진행 중이던 단계부터** 이어 간다. 이어받는 쪽은 항상 다른 CLI라 세션을 이을 수 없으므로 언제나 요약 인계다.
- 진행 중이던 단계의 반쯤 고친 파일: git 체크포인트가 있으면 **그 단계 시작 상태로 되돌리고 다시**(기본). 없으면 그대로 두고 그 단계에서 바뀐 파일 목록을 같이 넘긴다.
- `STEP` 표시가 없으면(가벼운 모델이 빼먹음) 실행이 끝날 때의 요약(바뀐 파일 + 마지막 출력)을 쓴다.
- 업무 기록에 `handoffs: [{from, to, fromAdapter, toAdapter, reason, at, costX}]`를 쌓는다. 화면에는 "A → B (한도)".
- 성과: 한도로 끝난 실행은 성과 기록(실행 수·실패)에 넣지 않는다. 인계받아 끝낸 기록은 따로 표시해 빠른 배정 통계에 섞지 않는다.

### 2-4. 설정
| 설정 | 기본 | 설명 |
|---|---|---|
| 한도 시 자동 이어받기 | 켜짐 | 끄면 지금처럼 대기 |
| 위 체급에게 넘기기 | 켜짐 | 같은 체급이 없을 때 |
| 비용이 오를 때 확인 | 2배 이상 | 사용량 가중치가 이 배수 이상 오르면 결재함에 묻는다(0 = 묻지 않음) |
| 기다림 한계 | 20분 | 초기화가 이 안이면(시각이 확실할 때) 기다린다 |
| 진행 중 단계 되돌리기 | 켜짐 | git 체크포인트가 있을 때 |

같은 연결 제외는 끌 수 없다(설명으로만). 이어받기 횟수 한도는 따로 두지 않는다: 아직 거치지 않은 연결이 남아 있는 동안만 넘긴다.

### 2-5. 그 밖
- A의 한도가 풀려도 업무를 돌려주지 않는다. 다음 새 업무부터 A를 쓴다.
- **사람이 넘기기**: 업무 상세의 [다른 직원에게 넘기기]가 같은 후보 목록을 보여 주고, 같은 요약 인계로 넘긴다(한도가 아니어도).
- **한도 예측**: 연결마다 "한도에 걸리기까지 쓴 실행 수"를 기억해 두고, 지금 그 85% 이상 썼으면 "곧 참"으로 보고 빠른 배정과 이어받기에서 뒤로 미룬다.
- **알림**: 이어받기는 소식판(업무 기록)과 데스크톱 알림에 "A → B (한도, 약 2배 비용)" 한 줄.
- **묶음 분산**: 한 번에 여러 업무를 넘길 때 같은 후보에게 몰리지 않게 이번에 받은 수를 센다.
- 탐색은 한도 감지 즉시, 그리고 기존 자동 실행 주기(4초)에서 한도 대기 업무만 다시 본다.
- **실제 한도 메시지 수집(7-3.5)**: 한도처럼 보이지만 감지 규칙에 안 맞는 실패 출력을 이 컴퓨터에 모아(최근 20개) 설정 화면에서 볼 수 있게 한다. 감지 문구를 실제 CLI 출력으로 맞추는 근거.

## 3. 작업 현황 탭
- 보드의 보기 전환에 **작업 현황**을 더한다.
- 왼쪽: 지금 일하는 직원만 한 줄로(구역 배치는 나중에). 결재 대기·자료 대기·한도 대기·오류인 직원도 멈춘 이유를 알리려고 보이되 말풍선 색으로 구분한다. 쉬는 직원은 "쉬는 직원 N명"으로 접는다.
- 직원 모습: 직무별 이모지 + 이름에서 정한 색. 상태 이름은 오피스의 `employeeState` 8가지를 그대로 쓴다. 동작은 CSS 몇 가지(타이핑, 돋보기, 손 듦, 졸음, 느낌표)이고 `prefers-reduced-motion`이면 끈다.
- 말풍선: 새 이벤트 채널 없이 **이미 있는 활동 이벤트**(`activity`, `live[taskId].last`)를 화면에서 문장으로 바꾼다(토큰 0). 파일은 이름만, 셸 명령은 종류(테스트·설치·git·그 외)만. 최소 1.5초 유지, 같은 문장 반복은 "계속 ○○ 중". CLI마다 자세함이 다르다: Claude는 도구별, Codex는 JSON 이벤트(실제 CLI 미검증), agy·직접 입력은 텍스트뿐이라 대부분 "작업 중…".
- 빈 화면: "일하는 직원 없음 — 할 일 N건(자동 실행 꺼짐)" 또는 "모두 한도 대기 — 가장 빠른 복귀 15:20"처럼 이유를 보여 준다.
- 오른쪽 진행 상황 사이드바: 업무마다 제목, 담당, 진행 막대(하위 업무가 있으면 완료 수/전체, 없으면 계획 단계), 이어받기 표시, 경과 시간. 정렬: 작업 중 → 결재·한도 대기 → 방금 끝난 것(10분, 흐리게). 누르면 사이드바 안에서 기존 업무 상세가 열린다(`TaskDetail`을 창 틀과 내용으로 나눠 재사용). 직원을 누르면 그 직원의 현재 업무 상세(활동 피드 포함)가 열린다.

## 4. 개발 단계
| 단계 | 내용 |
|---|---|
| 7-1 | 한도 실행을 성과 집계에서 제외, 인계 완료 기록 분리, 연결별 한도 예측 |
| 7-2 | 이어받기 후보 탐색(체급 순, 조건) 순수 함수 + 테스트 |
| 7-3 | 단계 저장 지점, 요약 인계와 `handoffs`, 자동 이어받기, 비용 확인 결재, 설정, 사람이 넘기기, 알림 |
| 7-3.5 | 한도로 보이는 미감지 출력 수집, 실제 CLI 한도 문구 확인(체크리스트) |
| 7-4 | 활동 이벤트 → 말풍선 문장(표) + 테스트 |
| 7-5 | 작업 현황 탭: 아바타, 말풍선, 동작, 빈 화면 |
| 7-6 | 진행 상황 사이드바와 업무 상세 재사용(`TaskDetail` 분리) |

## 5. 정한 것
1. 비용이 오를 때: 같은 체급은 자동, 사용량 가중치가 2배 이상 오르면 확인(설정으로 바꿈).
2. 말풍선은 한국어.
