## A. 로컬 AI 마무리

| # | 항목 | 상태 | 내용 |
|---|---|---|---|
| A1 | **한도 때문에 로컬로 이어받기** (v6 5-2, 8-5) | 구현 안 됨 | `handoffs.ts`가 `localModel` 직원을 후보에서 뺀다. 외부 CLI가 한도에 걸렸을 때 "적격한 로컬 직원"을 후보에 넣는다. 적격 조건: 쉬운 일 범위(파일 3개·24,000자 이하), 필요한 권한, 모델이 실제로 떠 있음. 부적격이면 강제로 넘기지 않는다. 사유를 구분해 기록(구독 한도 / PC 메모리 부족 / 서버 대기). |

## J. 내 PC AI 모델 목록 확장과 태그 (A6 상세)

### J-1. 왜 "전부"는 넣지 않나
2026-10-19에 Ollama 라이브러리(ollama.com/library)를 확인하니 **256개 모델**이 있다. 임베딩(검색용), 사진 읽기 전용, OCR, 안전 검사, 분류용, 의료용, 검열 해제 미세조정, 클라우드로만 도는 것이 섞여 있어서 **일을 맡기는 직원용으로는 대부분 맞지 않는다.** 그리고 모델마다 라이선스를 앱이 확인해 줄 수도 없다(앱은 "조건을 직접 확인했어요"를 사용자가 누르게 하는 구조). 그래서 두 층으로 나눈다.

| 층 | 내용 | 라이선스 표시 |
|---|---|---|
| ① 추천 목록(큐레이션) | 일을 맡길 만한 모델만 사람이 골라 데이터 파일에 넣는다. 태그가 붙는다. 약 20개 | 모델 카드에서 읽어 적고 `확인 전`으로 둔다 |
| ② 전체 찾기 | "다른 모델 찾기"에서 라이브러리를 이름·태그로 검색해 내려받는다. 앱은 목록만 보여주고 추천하지 않는다 | 항상 `확인 전`. 내려받기 전에 조건 링크를 열게 한다 |

①은 앱 업데이트 없이 갱신되게 데이터 파일(`local-models.json`)로 분리한다. 라이브러리 목록 가져오기(②)는 공식 페이지 형식이 바뀔 수 있어 실패하면 ①만 보이게 한다.

### J-2. 태그
한 모델에 여러 개가 붙는다. 앞의 두 종류는 Ollama가 정한 값을 그대로 쓰고, 나머지는 앱이 계산한다.

| 종류 | 태그 | 출처 |
|---|---|---|
| 능력 | `도구 호출`(tools), `생각하며 풀기`(thinking), `사진 보기`(vision), `검색용`(embedding) | Ollama 표시 |
| 용도 | `코딩`, `일반`, `번역·다국어`, `짧은 대화`, `긴 글`(128K 이상) | 사람이 큐레이션 |
| 크기 | `경량`(~4GB), `균형`(~10GB), `상위`(10GB 넘음) — 기존 등급과 같은 말 | 용량 기준 |
| 이 PC | `잘 맞아요` / `빠듯해요` / `이 PC엔 무거워요` | 앱이 PC 진단(메모리·그래픽 메모리)과 모델 용량을 비교 |
| 상태 | `설치됨`, `추천`, `쓰는 중` | 앱 |
| 주의 | `라이선스 확인 전`, `영어 위주`, `오래된 모델` | 큐레이션 |

- 직원용 후보 화면에서는 **`도구 호출`이 있고 `검색용`·`사진 전용`이 아닌 것**만 기본으로 보인다. 앱이 이끄는 수정 방식(모델은 수정 내용만 돌려줌)은 도구 호출이 없어도 되므로, `도구 호출`이 없는 모델은 "쉬운 일만" 범위에서만 직원으로 쓰게 한다고 표시한다.
- **`추천`은 PC 기준**이다. 이 PC에서 `잘 맞아요`이고 `코딩` 또는 `일반`이며 실측(앱의 속도·품질 시험)을 통과한 것에만 붙는다. 실측 전에는 "추천 후보"로만 쓴다. 내가 임의로 순위를 정하지 않는다.
- 목록은 필터 칩(`코딩`, `이 PC에 맞음`, `설치됨`…)과 정렬(추천순, 크기순, 인기순)을 지원한다.

### J-3. 큐레이션 후보 (1차안, 라이선스는 전부 확인 전)
Ollama 인기·최신 목록에서 **텍스트로 일을 할 수 있고, 로컬 PC에서 돌 크기**인 것만 뽑은 초안이다. 정확한 용량·라이선스는 담을 때 각 모델 카드에서 읽어 적는다(지금 추측으로 채우지 않는다).

| 등급 | 후보 | 용도 |
|---|---|---|
| 경량 | llama3.2 3b · phi4-mini 3.8b · granite4 3b · qwen3 4b · gemma3 4b · ministral-3 3b | 짧은 대화·요약, 작은 수정 |
| 균형 | qwen2.5-coder 7b·14b(지금 있음) · qwen3 8b·14b · llama3.1 8b · gemma3 12b · phi4 14b · granite4.1 8b · deepseek-r1 8b·14b(생각하며 풀기) | 코딩, 일반 |
| 상위 | qwen2.5-coder 32b(지금 있음) · qwen3-coder 30b · devstral 24b · mistral-small 24b · gemma3 27b · gpt-oss 20b | 코딩, 도구 호출 |

넣지 않는 것: 검색용(nomic-embed-text, bge, mxbai 등), 사진·OCR 전용(llava, glm-ocr 등), 안전 검사(llama-guard, shieldgemma), 분류·결정용, 의료용, 검열 해제 미세조정(dolphin 등), 클라우드로만 도는 모델(`cloud` 표시), 100B 넘는 모델, 단종된 오래된 모델(llama2, vicuna 등).

주의: 위 이름은 Ollama가 지금 보여 주는 이름이고 새 모델이 계속 나온다. 그래서 목록은 앱에 박지 않고 데이터 파일로 둔다.

### J-4. 라이선스
- 지금의 `조건을 직접 확인했어요` 단계를 유지한다. 모델마다 `licenseName`·`licenseUrl`·확인 여부를 가진다(구조 이미 있음).
- 라이선스 이름은 모델 카드에서 읽어 적되, "상용 앱에서 쓰거나 다시 배포해도 되는지"는 **앱이 판단하지 않는다.** 사용자가 읽고 누른다.
- Llama 계열은 별도 커뮤니티 라이선스(조건이 다름), Qwen 일부 크기는 Apache-2.0이 아닌 별도 조건이 있을 수 있으므로 크기별로 따로 적는다.

### J-5. 구현 단계
| 단계 | 내용 | 예상 토큰 |
|---|---|---|
| J1 | 모델 데이터에 `tags`·`kind` 필드와 파서, 목록을 `local-models.json`으로 분리 | 4~6만 |
| J2 | 큐레이션 20개 담기(각 모델 카드에서 용량·라이선스 읽기) | 6~10만 |
| J3 | 화면: 태그 칩, 필터·정렬, `이 PC` 태그 계산 | 8~12만 |
| J4 | "다른 모델 찾기"(라이브러리 목록 가져와 검색, 실패하면 숨김) | 6~9만 |
| 합계 | | 약 24~37만 |

### J-6. 정할 것
1. 큐레이션 20개 안에 빠지거나 넣고 싶은 모델이 있는지.
2. "다른 모델 찾기"(②)를 넣을지. 넣으면 앱이 인터넷에서 목록을 가져온다.
3. `추천` 태그를 실측 통과에만 붙이는 것으로 충분한지(실측 전엔 아무것도 추천이 아님).
